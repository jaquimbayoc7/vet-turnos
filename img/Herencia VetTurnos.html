Abstracción, encapsulamiento y herencia en Vet Turnos

El código que dibuja la lista nunca pregunta si el paciente es un perro, un gato o un ave: solo conoce el contrato de Mascota. Los datos están protegidos por campos privados, y cada especie reutiliza por herencia lo que tiene en común y solo agrega lo propio.

1. Abstracción: el contrato de Mascota

La clase base no se puede usar sola

new Mascota() falla con un Error, porque new.target detecta la creación directa.

El contrato obliga a implementar

Si una subclase olvida hacerSonido(), la llamada lanza un Error en vez de devolver algo vacío.

Agregar un animal toca pocos lugares

Una clase nueva que extienda Mascota, una entrada en fabricas y sus opciones del formulario. dibujar() no cambia: así entró Ave.

2. Encapsulamiento: datos privados, acceso controlado

#peso es privado

El prefijo # impide leerlo o escribirlo desde fuera de la clase. Solo get peso y set peso lo tocan, y ni siquiera Perro, Gato o Ave pueden acceder a él directamente.

El setter valida los cambios

Cualquier mascota.peso = valor con un valor no numérico, cero o negativo lanza RangeError. El constructor asigna this.#peso directamente; para validar también en el alta bastaría con this.peso = peso.

#pacientes no se expone

registrar() es la única puerta de entrada y el getter devuelve una copia, así que push externo no altera la lista real.

El formulario muestra el error

El try/catch del submit captura el RangeError o el TypeError y lo escribe en #mensaje con la clase error.

Cómo se comporta el código

// El setter protege el campo privado
const p = new Perro("Rex", 12, "Labrador");
p.peso = 15;            // ok: pasa por set peso()
p.peso = -3;            // RangeError: El peso debe ser un número positivo o mayor a cero
p.#peso;                // SyntaxError: fuera de la clase no existe

// La lista de pacientes queda aislada
clinica.registrar(p);
clinica.pacientes.push({});   // solo altera la copia
clinica.pacientes.length;     // sigue siendo 1
clinica.registrar({});        // TypeError: Solo se pueden registrar instancias de Mascota

3. Herencia: lo común en Mascota, lo propio en cada especie

super() reutiliza el constructor

Cada subclase pasa nombre, peso y su especie al padre, y solo guarda su campo propio: raza, deInterior o puedeVolar.

describir() extiende, no reescribe

Las subclases llaman a super.describir() y le agregan su texto. Así leen el peso privado sin acceder a #peso: lo hace el padre por ellas.

El polimorfismo se mantiene

dibujar() sigue llamando a m.describir() y m.hacerSonido() sin saber la clase. Cada objeto responde según su propia subclase.

Las tres ideas trabajan juntas

La abstracción define qué se puede pedir, el encapsulamiento protege el estado y la herencia evita repetir código entre especies.

Herencia y polimorfismo en acción

// Cada especie se crea con su fábrica; el formulario solo conoce el tipo
fabricas.Perro("Rex", 12, "Labrador");      // new Perro(nombre, peso, extra)
fabricas.Gato("Misu", 4, "De interior");     // new Gato(nombre, peso, extra === "De interior")
fabricas.Ave("Pío", 0.3, "Puede Volar");     // new Ave(nombre, peso, extra === "Puede Volar")

// dibujar() trata a todos igual
for (const m of clinica.pacientes) {
  m.describir();     // "Nombre: Rex, Peso: 12 Kg, Especie: perro, Raza: Labrador"
  m.hacerSonido();   // "Guau Guau" / "Miau Miau" / "Pío Pío"
}

4. Diagrama de clases

Una jerarquía, una colección

Mascota, Perro, Gato y Ave forman la jerarquía. Clinica es independiente y solo conoce el tipo Mascota.

Un atributo propio por subclase

Lo común (nombre, especie, #peso) vive en el padre. raza, deInterior y puedeVolar viven solo donde tienen sentido.

Polimorfismo en dos métodos

La misma llamada a hacerSonido() o describir() da un resultado distinto según la clase concreta, sin condicionales en dibujar().

Lo privado no cruza el borde

Los dos únicos miembros con - son #peso y #pacientes; todo lo demás es la interfaz pública.
